## 1. Evidence model

Stage VII-F2 separates two kinds of evidence deliberately:

1. **Immutable predecessor evidence** — the last fully validated commit before F2, recorded below with exact GitHub Actions run IDs and artifact digests.
2. **Exact F2 candidate evidence** — generated by CI after the commit containing this report exists. The `stage7-acceptance-evidence` artifact is keyed to `${{ github.sha }}` and can therefore identify the exact candidate without the self-referential error of embedding its own future commit SHA in source text.

A green F2 branch candidate is still not Stage VII acceptance. Governed integration to `main` and the required III–VII rerun on `main` remain mandatory.

## 6. Stage VII control evidence

### Deployment and deterministic build

- Locked frontend installation uses `npm ci`.
- Pages uses the repository subpath `/empirical-finance-lab/`.
- Production artifacts are built once, manifest-hashed, smoke-tested, re-hashed, then deployed without rebuilding.
- Browser build provenance is tied to the exact Git commit through `EFL_BUILD_COMMIT`.

### Security and privacy

- Document CSP is enforcing and excludes `unsafe-inline` and `unsafe-eval`.
- Referrer Policy is `no-referrer`.
- Document code has no direct jsDelivr grant; the dedicated worker has its separately audited pinned-runtime initialization boundary.
- Scientific analysis-phase network requests are required to remain zero in local production and live deployment tests.
- Research CSVs are opened locally in browser memory; EFL provides no research-data upload endpoint.

### Supply chain

- External GitHub Actions references are frozen to full 40-character commit SHAs.
- npm and GitHub Actions Dependabot update policy is version-controlled.
- Scientific Python dependencies are intentionally excluded from automatic update policy and require deliberate parity review.
- Repository-wide enforcement of full action-SHA pins remains intentionally deferred until the pinned Stage VII workflows are integrated to `main`.

### Provenance and reproducibility

- Browser and Python scientific-core build commits must agree.
- Build mode/source are recorded as `github-pages` / `github-actions` for the validated Pages candidate.
- AnalysisID and ExecutionID definitions are not redefined by Stage VII.
- The reproducibility ZIP performs a byte-checked round trip, reconstructs the archived analysis, reruns the browser engine, and requires a byte-identical re-export.

### Onboarding

The deterministic synthetic tutorial remains independently generated and checked. Its frozen known answer is:

- AR(-1): `+1.000%`
- AR(0): `+3.000%`
- AR(+1): `-1.000%`
- CAR[-1,+1]: `+3.000%`

### Accessibility and responsive behavior

Automated Stage VII checks cover:

- skip-link focus target;
- progress semantics;
- tab/panel ARIA relationships;
- Arrow/Home/End keyboard tab navigation;
- visible file-input focus;
- keyboard-scrollable result tables;
- native `hidden` semantics; and
- completed-result containment at `320`, `390`, `768`, and `1280` CSS-pixel widths.

This is an automated product contract, **not a WCAG certification and not manual assistive-technology user testing**.

## 7. F2 exact-candidate evidence artifact

When deployment and live verification succeed, the Stage VII workflow runs a final `evidence` job that depends on `build`, `deploy`, and `verify-live`.

That job writes:

and uploads it as:

The JSON records, at minimum:

- exact observed evidence-job Python/Node/npm versions;

- exact locked frontend-development versions;
- exact Playwright Chromium/Firefox/WebKit browser versions and revisions;
- SHA-256 hashes of critical repository authority files;
- every external GitHub Action full-SHA pin; and
- the explicit boundary that branch evidence completion is **not** Stage VII acceptance on `main`.

## 8. Known limitations and deferred repository actions

1. Stage VII remains a release-hardening candidate until governed `main` integration and a green III–VII main-branch rerun.
2. The public Pages candidate remains `noindex,nofollow` and must not be described as Public Beta.
3. No formal `v0.1.0` release or version-specific DOI exists.
4. Runtime initialization can contact the pinned jsDelivr Pyodide host; the privacy guarantee applies to the scientific **analysis phase**, which is required to make zero network requests.
5. Accessibility evidence is automated and bounded; it does not substitute for formal conformance auditing or manual assistive-technology testing.
6. Dependabot alerts/security updates were enabled by repository administration during Stage VII; that settings state was user-confirmed when the integration could not independently read the setting through the GitHub API.
7. The temporary `stage-vii-release-hardening` deployment allowance in the `github-pages` environment remains until Stage VII is integrated to `main`.
8. Repository-wide GitHub Actions full-SHA enforcement remains deferred until the pinned workflows are present and revalidated on `main`.

## 9. Acceptance decision rule

The F2 feature-branch tranche is complete only if the commit containing this report:

1. passes the F2 static evidence gate;
2. passes Stages III–VII on the exact commit, with any rerun disclosed;
3. deploys the exact tested production artifact;
4. passes live HTTPS verification; and
5. emits the `stage7-acceptance-evidence` artifact for that exact commit.

Even then, the decision is **“Stage VII branch candidate ready for governed integration”**, not “Stage VII accepted.” Final Stage VII acceptance requires the post-integration III–VII run on `main`.
